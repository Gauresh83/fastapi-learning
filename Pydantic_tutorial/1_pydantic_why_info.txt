# Pydantic Model, Field and Validation

## What is Pydantic?

Pydantic is a Python library used to validate and structure data using Python type hints.

It is commonly used with FastAPI because it makes it easy to define what type of data an API should accept.

For example:

```python
class Patient(BaseModel):
    name: str
    age: int
```

Here, `Patient` is a Pydantic model and it expects:

* `name` to be a string
* `age` to be an integer

When we create the object, Pydantic checks the data.

```python
patient = Patient(name="John", age=30)
```

---

## BaseModel

```python
from pydantic import BaseModel
```

`BaseModel` is the main class used for creating Pydantic models.

```python
class Patient(BaseModel):
    name: str
    age: int
```

Because `Patient` inherits from `BaseModel`, Pydantic automatically performs validation when we create a `Patient` object.

---

# Field

```python
from pydantic import Field
```

`Field()` is used when we want to add extra rules or information to a field.

Example:

```python
age: int = Field(ge=0, le=120)
```

This means the age must be:

```text
greater than or equal to 0
and
less than or equal to 120
```

So:

```text
0       -> valid
25      -> valid
120     -> valid
-5      -> invalid
150     -> invalid
```

---

# Annotated

```python
from typing import Annotated
```

`Annotated` allows us to attach extra information or validation rules to a type.

Example:

```python
name: Annotated[str, Field(max_length=50)]
```

This means:

```text
name must be a string
+
name can have maximum 50 characters
```

Another example from the code:

```python
weight: Annotated[float, Field(gt=0, strict=True)]
```

Here:

* `float` means the value should be a float
* `gt=0` means the value must be greater than 0
* `strict=True` means Pydantic should use strict type checking for this field

---

# max_length

```python
Field(max_length=50)
```

`max_length` specifies the maximum number of characters allowed in a string.

Example:

```python
name: Annotated[str, Field(max_length=50)]
```

This is valid:

```python
name = "John Doe"
```

But a string containing more than 50 characters will fail validation.

---

# title

```python
Field(title="Name of the patient")
```

`title` is mainly used as metadata.

It gives the field a readable title and can appear in generated JSON Schema and FastAPI documentation.

It does not perform validation.

---

# description

```python
Field(
    description="This field is used to store the name of the patient"
)
```

`description` provides additional information about the field.

It is useful when generating API documentation.

For example, FastAPI can show this description in Swagger UI.

---

# ge

`ge` means:

```text
greater than or equal to
```

Example:

```python
age: int = Field(ge=0)
```

means:

```text
age >= 0
```

So `0` is allowed.

---

# le

`le` means:

```text
less than or equal to
```

Example:

```python
age: int = Field(le=120)
```

means:

```text
age <= 120
```

When we combine both:

```python
age: int = Field(ge=0, le=120)
```

we get:

```text
0 <= age <= 120
```

---

# gt

`gt` means:

```text
greater than
```

Example:

```python
weight: Annotated[float, Field(gt=0)]
```

means:

```text
weight > 0
```

So:

```text
70.5  -> valid
1.5   -> valid
0     -> invalid
-5    -> invalid
```

The difference between `gt` and `ge` is:

```text
gt=0  -> value must be greater than 0
ge=0  -> value can be greater than or equal to 0
```

---

# strict=True

```python
weight: Annotated[float, Field(gt=0, strict=True)]
```

`strict=True` tells Pydantic to be strict about the field's type instead of freely converting compatible input types.

For example, without strict validation, Pydantic may accept a string such as:

```python
"70.5"
```

and convert it to a number.

With strict validation, the input needs to already have the expected numeric type.

This is useful when we don't want automatic type conversion for a particular field.

---

# Optional

```python
from typing import Optional
```

`Optional` means a field can contain a value or `None`.

Example:

```python
linkedin: Optional[AnyUrl]
```

means:

```text
linkedin can contain a URL
OR
linkedin can be None
```

If we also want the field to be optional when creating the model, we normally give it a default:

```python
linkedin: Optional[AnyUrl] = None
```

---

# AnyUrl

```python
from pydantic import AnyUrl
```

`AnyUrl` is a Pydantic type used for validating URLs.

In the code:

```python
linkedin: Optional[AnyUrl] = Field(default=None)
```

we expect the LinkedIn field to contain a valid URL or `None`.

Example:

```python
linkedin = "https://www.linkedin.com/in/johndoe"
```

Pydantic checks the URL format.

---

# EmailStr

```python
from pydantic import EmailStr
```

`EmailStr` is used for validating email addresses.

Example:

```python
email: EmailStr
```

Pydantic checks that the value looks like a valid email address.

For example:

```text
john.doe@example.com
```

is a valid email format.

---

# List

```python
from typing import List
```

`List[str]` means a list where the values should be strings.

Example:

```python
allergies: Optional[List[str]]
```

Possible value:

```python
["Peanuts", "Milk", "Dust"]
```

Each item in the list should be a string.

---

# Dict

```python
from typing import Dict
```

`Dict[str, str]` means a dictionary where:

```text
key   -> string
value -> string
```

Example:

```python
contact_details = {
    "phone": "123-456-7890",
    "address": "123 Main St, Anytown, USA"
}
```

Both the keys and values are strings.

# Patient Model

The complete model is:

```python
class Patient(BaseModel):
    name: Annotated[
        str,
        Field(
            max_length=50,
            title="Name of the patient",
            description="This field is used to store the name of the patient"
        )
    ]

    age: int = Field(ge=0, le=120)

    weight: float = Annotated[
        float,
        Field(gt=0, strict=True)
    ]

    married: Annotated[
        bool,
        Field(
            default=None,
            description="This field is used to store the marital status of the patient"
        )
    ]

    linkedin: Optional[AnyUrl] = Field(default=None)

    allergies: Optional[List[str]] = Field(default=None)

    email: EmailStr = Field(default=None)

    contact_details: Dict[str, str] = Field(default=None)
```

The model defines the expected structure of patient data.

# Creating Patient Data

We first create a normal Python dictionary:

```python
patient_info = {
    "name": "John Doe",
    "age": 30,
    "weight": 70.5,
    "linkedin": "https://www.linkedin.com/in/johndoe",
    "married": True,
    "email": "john.doe@example.com",
    "allergies": ["Peanuts"],
    "contact_details": {
        "phone": "123-456-7890"
    }
}
```

This dictionary contains all the patient information.

---

# What does `**patient_info` mean?

We create the Pydantic model using:

```python
patient1 = Patient(**patient_info)
```

The `**` operator unpacks a dictionary.

So this:

```python
Patient(**patient_info)
```

is basically the same as:

```python
Patient(
    name="John Doe",
    age=30,
    weight=70.5,
    linkedin="https://www.linkedin.com/in/johndoe",
    married=True,
    email="john.doe@example.com",
    allergies=["Peanuts"],
    contact_details={
        "phone": "123-456-7890"
    }
)
```

---

# What happens when `Patient()` is created?

When we execute:

```python
patient1 = Patient(**patient_info)
```

Pydantic checks the supplied data.

The general flow is:

```text
patient_info
     |
     v
Patient(**patient_info)
     |
     v
Pydantic validation
     |
     +---- name -> string, max 50 characters
     |
     +---- age -> integer, 0 to 120
     |
     +---- weight -> float, greater than 0
     |
     +---- married -> boolean
     |
     +---- linkedin -> valid URL
     |
     +---- email -> valid email
     |
     +---- allergies -> list of strings
     |
     +---- contact_details -> dictionary
     |
     v
Patient object
```

If the data doesn't satisfy the rules, Pydantic raises a validation error.

# Why Pydantic is Useful

Without Pydantic, we would have to manually check every value.

For example:

```python
if not isinstance(age, int):
    ...

if age < 0:
    ...

if age > 120:
    ...

if not isinstance(allergies, list):
    ...
```

Pydantic handles much of this automatically through type hints and field definitions.

This becomes especially useful in FastAPI APIs.

For example:

```python
@app.post("/patients")
def create_patient(patient: Patient):
    return patient
```

FastAPI can use the `Patient` model to validate incoming JSON data automatically.

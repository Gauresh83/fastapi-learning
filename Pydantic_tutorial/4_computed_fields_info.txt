# Pydantic Computed Field

## What is a Computed Field?

A **computed field** is a value that is calculated from other fields in a Pydantic model.

The value is not directly provided by the user.

For example, in a patient model we have:

```python
weight: float
height: float
```

We can calculate BMI from these two values:

```text
BMI = weight / height²
```

Instead of asking the user to provide BMI, we calculate it automatically.

Pydantic provides:

```python
@computed_field
```

for this purpose.

---

# Importing `computed_field`

```python
from pydantic import computed_field
```

It is used when a value should be calculated from existing model data.

---

# Basic Syntax

The common pattern is:

```python
@computed_field
@property
def field_name(self) -> return_type:
    # calculation
    return result
```

Example:

```python
@computed_field
@property
def calculate_bmi(self) -> float:
    return round(self.weight / (self.height ** 2), 2)
```

Here:

* `@computed_field` tells Pydantic this calculated value should be treated as a model field.
* `@property` allows us to access the calculation like an attribute.
* `self` represents the current `Patient` object.
* `-> float` says the result is expected to be a float.

---

# What is `@property`?

Normally, a method is called using parentheses:

```python
patient.calculate_bmi()
```

But when we use:

```python
@property
```

we can access it like an attribute:

```python
patient.calculate_bmi
```

For example:

```python
class Patient:

    @property
    def calculate_bmi(self):
        return self.weight / (self.height ** 2)
```

Then:

```python
patient.calculate_bmi
```

runs the method automatically.

We don't need:

```python
patient.calculate_bmi()
```

---

# Why Use `@computed_field`?

`@property` alone creates a calculated property, but Pydantic doesn't treat a normal property as a model field for serialization/schema purposes.

Adding:

```python
@computed_field
```

tells Pydantic:

> Include this computed value as part of the model's fields when appropriate, such as when dumping/serializing the model.

So:

```python
@computed_field
@property
def calculate_bmi(self):
```

means:

```text
Calculate the value
        +
Treat it as a Pydantic computed field
```

# Computed Field vs Field

## Normal Field

```python
weight: float
```

The value comes from the input.

```json
{
    "weight": 70.5
}
```

## Computed Field

```python
@computed_field
@property
def calculate_bmi(self) -> float:
    return round(self.weight / self.height ** 2, 2)
```

The value is calculated from existing fields.

```text
weight + height
       ↓
      BMI
```

---

# Computed Field vs Validator

These two concepts are different.

## Validator

A validator is generally used to:

* Check whether data is valid
* Reject invalid data
* Normalize/transform input

Example:

```python
@field_validator("age")
@classmethod
def validate_age(cls, value):
    if value < 0:
        raise ValueError("Age cannot be negative.")

    return value
```

The validator answers:

> Is this data valid?

---

## Computed Field

A computed field calculates a value.

Example:

```python
@computed_field
@property
def calculate_bmi(self) -> float:
    return round(self.weight / self.height ** 2, 2)
```

It answers:

> What value can I calculate from the existing data?

---

# Simple Difference

```text
Validator
    ↓
Check / clean / transform data

Computed Field
    ↓
Calculate a value from existing data
```

---

# Computed Field vs Model Validator

A model validator can check relationships between multiple fields.

Example:

```python
@model_validator(mode="after")
def validate_patient(self):
    if self.age > 60 and "emergency" not in self.contact_details:
        raise ValueError("Emergency contact required.")

    return self
```

This validates a rule.

A computed field calculates something:

```python
@computed_field
@property
def calculate_bmi(self) -> float:
    return round(self.weight / self.height ** 2, 2)
```

So:

```text
model_validator
    ↓
Check if model is valid

computed_field
    ↓
Calculate information from model
```

# Computed Fields and `model_dump()`

One useful feature of `computed_field` is that Pydantic can include the computed value when serializing the model.

For example:

```python
patient1.model_dump()
```

can include the computed field:

```python
{
    "name": "John Doe",
    "email": "john.doe@hdfc.com",
    "age": 30,
    "weight": 70.5,
    "height": 1.75,
    "married": True,
    "allergies": ["penicillin", "shellfish"],
    "contact_details": {
        "phone": "123-456-7890",
        "address": "123 Main St, Anytown, USA",
        "emergency": "123-456-7890"
    },
    "calculate_bmi": 23.02
}
```

The exact output depends on how the model is serialized, but the important point is that `computed_field` makes the calculated property part of Pydantic's serialization/schema handling.

# Why This Is Useful in FastAPI

Computed fields are useful when an API needs to return information that can be calculated from stored data.

```text
    |
```

The client doesn't need to calculate BMI itself.

The backend can calculate it.

# Complete Code

```python
from pydantic import BaseModel, Field, AnyUrl, EmailStr, computed_field
from typing import Optional, List, Dict, Annotated


class Patient(BaseModel):

    name: str
    email: EmailStr
    age: int
    weight: float
    height: float
    married: Optional[bool]
    allergies: List[str]
    contact_details: Dict[str, str]

    @computed_field
    @property
    def calculate_bmi(self) -> float:
        bmi = round(self.weight / (self.height ** 2), 2)
        return bmi


def update_patient_data(existing_patient: Patient):

    print(existing_patient.name)
    print(existing_patient.age)
    print(existing_patient.weight)
    print("BMI", existing_patient.calculate_bmi)
    print(existing_patient.married)
    print(existing_patient.allergies)
    print(existing_patient.contact_details)

    print("Patient data updated successfully.")


patient_info = {
    "name": "John Doe",
    "age": 30,
    "weight": 70.5,
    "height": 1.75,
    "married": True,
    "email": "john.doe@hdfc.com",
    "allergies": ["penicillin", "shellfish"],
    "contact_details": {
        "phone": "123-456-7890",
        "address": "123 Main St, Anytown, USA",
        "emergency": "123-456-7890"
    }
}


patient1 = Patient(**patient_info)

update_patient_data(patient1)
```

```text

    → Adds constraints/metadata

    → Combines a type with metadata

    → Allows None

    → Validates email addresses

    → Validates URLs

    → Validates one field
```

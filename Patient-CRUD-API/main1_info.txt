# FastAPI Patient API

This project is a simple FastAPI application for managing patient data.

It demonstrates:

* Pydantic `BaseModel`
* `Field()` and `Annotated`
* `Literal`
* `computed_field`
* `Path()`
* `Query()`
* `HTTPException`
* `JSONResponse`
* GET requests
* POST requests
* Reading and writing JSON files
* Sorting patient data
* Automatic validation using Pydantic

---

# 1. Importing Required Modules

```python
from fastapi import FastAPI, Path, HTTPException, Query
```

These are imported from FastAPI.

### `FastAPI`

Used to create the FastAPI application.

```python
app = FastAPI()
```

### `Path`

Used to add validation and documentation to path parameters.

Example:

```text
/patient/P001
```

Here `P001` is a path parameter.

### `Query`

Used to add validation and documentation to query parameters.

Example:

```text
/sort?sort_by=height&order=asc
```

### `HTTPException`

Used when we want to return an HTTP error response.

Example:

```python
raise HTTPException(
    status_code=404,
    detail="Patient not found"
)
```

# 16. What is `@property`?

Normally, a method is called using:

```python
patient.bmi()
```

But when we use:

```python
@property
```

we can access it like an attribute:

```python
patient.bmi
```

So:

```python
@property
def bmi(self):
```

allows:

```python
patient.bmi
```

instead of:

```python
patient.bmi()
```

---

# 17. What is `@computed_field`?

`@computed_field` tells Pydantic that this calculated property should also be treated as a field during serialization/schema generation.

For example:

```python
patient.model_dump()
```

can include:

```text
bmi
verdict
```

along with the normal model fields.

---

# 18. BMI Calculation

The code is:

```python
@computed_field
@property
def bmi(self) -> float:

    bmi = round(
        self.weight / (self.height ** 2),
        2
    )

    return bmi
```

The BMI formula is:

```text
BMI = weight / height²
```

where:

```text
weight = kilograms
height = meters
```

---

# 19. Example BMI

Suppose:

```text
weight = 70.5 kg
height = 1.75 m
```

Then:

```text
BMI = 70.5 / (1.75²)
```

which gives approximately:

```text
23.02
```

Therefore:

```python
patient.bmi
```

returns:

```text
23.02
```

# 21. Patient Verdict

The code is:

```python
@computed_field
@property
def verdict(self) -> str:

    if self.bmi < 18.5:
        return "Underweigth"

    elif self.bmi < 25:
        return "Normal"

    elif self.bmi < 30:
        return "Normal"

    else:
        return "Obese"
```

The verdict is calculated using BMI.

The current logic is:

```text
BMI < 18.5
    ↓
Underweigth

18.5 <= BMI < 25
    ↓
Normal

25 <= BMI < 30
    ↓
Normal

BMI >= 30
    ↓
Obese
```

Notice that your code currently returns `"Normal"` for both:

```python
18.5 <= BMI < 25
```

and:

```python
25 <= BMI < 30
```

If your intention is to use the common BMI categories, the second condition would normally return `"Overweight"`:

```python
elif self.bmi < 30:
    return "Overweight"
```

Also, `"Underweigth"` is a spelling mistake. It should be:

```text
Underweight
```

---

# 22. Corrected Verdict

A cleaner version would be:

```python
@computed_field
@property
def verdict(self) -> str:

    if self.bmi < 18.5:
        return "Underweight"

    elif self.bmi < 25:
        return "Normal"

    elif self.bmi < 30:
        return "Overweight"

    else:
        return "Obese"
```

# 44. Important Point About BMI in `/sort`

There is an important issue in the current code.

Your `Patient` model has:

```python
@computed_field
@property
def bmi(self):
```

but `/sort` is sorting raw dictionaries loaded directly from:

```text
patients.json
```

If the JSON file contains only:

```text
id
name
city
age
gender
height
weight
```

and does **not** contain `bmi`, then:

```python
x.get("bmi", 0)
```

returns:

```text
0
```

for every patient.

So sorting by BMI will not work correctly unless `bmi` is stored in the JSON or calculated before sorting.

This is an important difference between:

```text
Pydantic model
```

and:

```text
raw JSON dictionary
```

# 51. `exclude=["id"]`

Your code uses:

```python
patient.model_dump(exclude=["id"])
```

This removes the `id` field from the dictionary.

Why?

Because the ID is already being used as the dictionary key:

```python
data[patient.id] = ...
```

So storing the ID again inside the patient object is unnecessary in this particular JSON structure.

The structure becomes conceptually:

```json
{
    "P003": {
        "name": "John",
        "city": "Delhi",
        "age": 30
    }
}
```

instead of:

```json
{
    "P003": {
        "id": "P003",
        "name": "John",
        "city": "Delhi"
    }
}
```

# Path Parameter vs Query Parameter

This is an important FastAPI interview concept.

## Path Parameter

Example:

```text
/patient/P001
```

Code:

```python
@app.get("/patient/{patient_id}")
```

Here:

```text
patient_id
```

is part of the URL path.

Used when identifying a specific resource.

---

## Query Parameter

Example:

```text
/sort?sort_by=height&order=asc
```

Code:

```python
def sort_patients(
    sort_by: str = Query(...),
    order: str = Query("asc")
):
```

Here:

```text
sort_by
order
```

are query parameters.

They are generally used for filtering, sorting, searching, pagination, etc.
